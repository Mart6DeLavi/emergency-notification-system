# SENSA iOS

Native SwiftUI client for the SENSA emergency notification system.

## What is implemented

- Sign in and registration with full address fields.
- Report list scoped to the signed-in user (`GET /api/v1/emergencies/my`).
- Two-phase report creation:
  1. fill in the incident details and select photos/videos;
  2. upload the batch to moderation, see per-file `Approved` / `Rejected`
     results, remove rejected files, then create the report and link the
     approved files to it (`PATCH /api/v1/files/link`).
- Report detail with a status timeline (`Reported` → `Under review` →
  `Confirmed` → `Broadcast`, plus `Rejected`) and background refresh.
- Profile: personal data, address, push/email/SMS notification settings,
  language switch (English / Polish), sign out.
- JWT stored in the Keychain; expired tokens sign the user out automatically.

Push notifications are intentionally not implemented yet. They need an APNs
certificate, Firebase Cloud Messaging configuration and a backend change from
an API key to a service-account OAuth2 token.

## Requirements

- iOS 17.0+ (verified on iOS 17.2+).
- No local Xcode installation is required for this repository: the project is
  generated with XcodeGen and built in Codemagic on a macOS machine.
- [Codemagic](https://codemagic.io) account connected to the GitHub repository.
- [Appetize.io](https://appetize.io) account for running the simulator build in
  a browser.

## API configuration

Production base URL:

```
https://panel.sensanotify.com/api
```

The client appends `/v1/...` to it. For a local backend, set the
`API_BASE_URL` environment variable in the Xcode scheme, for example:

```
API_BASE_URL=http://localhost:8080
```

`NSAllowsLocalNetworking` is enabled so the simulator can reach a local
gateway over HTTP. Release builds always use HTTPS.

Backend endpoints used by the app:

| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/auth/register` | create account |
| POST | `/v1/auth/login` | obtain JWT |
| GET | `/v1/users/{userId}` | profile |
| PATCH | `/v1/users/{userId}` | profile, notification settings |
| POST | `/v1/files` | batch upload, per-file moderation |
| PATCH | `/v1/files/link` | link approved files to a report |
| POST | `/v1/emergencies` | create a report |
| GET | `/v1/emergencies/my` | current user's reports |
| GET | `/v1/emergencies/{id}` | report details and status |

## Build and test locally (macOS with Xcode)

```bash
cd mobile/ios
brew install xcodegen
xcodegen generate
xcodebuild -project SENSA.xcodeproj -scheme SENSA \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build

xcodebuild test -project SENSA.xcodeproj -scheme SENSA \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  CODE_SIGNING_ALLOWED=NO
```

`Info.plist` and `SENSA.xcodeproj` are generated and ignored by Git.

## Codemagic

The root `codemagic.yaml` defines the `sensa-ios-simulator` workflow:

1. install XcodeGen;
2. generate the project;
3. build for the iOS simulator;
4. run unit tests;
5. package `SENSA.app` as `SENSA-simulator.zip`.

The workflow triggers on pushes to the `ios-app` branch. Create a Codemagic
application for this repository and select the `ios-app` branch; Codemagic will
pick up `codemagic.yaml` automatically.

Download the artifact from the build page and upload it to Appetize.io
(choose an iPhone simulator, iOS 17.2 or newer). Appetize can also be
automated through its API; keep the API key in Codemagic environment variables,
never in Git.

### Path filters

Codemagic does not provide native path filters for GitHub push triggers. The
workflow currently listens only to `ios-app`, so backend pushes to `master` do
not start iOS builds. After merging to `master`, add either a dedicated
workflow branch or a small GitHub Action that calls the Codemagic API only when
`mobile/ios/**` or `codemagic.yaml` changes.

## Localization

English UI strings are the localization keys. Polish translations live in
`Sources/Resources/pl.lproj/Localizable.strings`. The language can be switched
in Profile → Language; the choice is stored in `@AppStorage("appLanguage")`.

## Known limitations

- No push notifications yet (APNs/FCM + backend OAuth2 work is pending).
- No map or geolocation; the user enters country, city and street manually.
- Videos are loaded into memory before upload. For very large files a future
  iteration should stream from a temporary file.
- JWT lifetime is 24 hours; after expiry the app signs the user out and asks
  them to log in again.
- Server-side validation errors are shown as returned by the backend (English).

## Troubleshooting

- `xcodegen: command not found` — run `brew install xcodegen`.
- `No such module 'SENSA'` in tests — regenerate the project with
  `xcodegen generate` and make sure the `SENSATests` target exists.
- Photo picker does not open — check `NSPhotoLibraryUsageDescription` in the
  generated `Info.plist`.
- `401 Unauthorized` — the JWT expired or `JWT_USER_SECRET` changed on the
  server; sign in again.
